## 오늘의 질문

하나의 웹 요청이 다른 컴퓨터에 도착하기까지 필요한 복잡한 통신 과정을 어떻게 나누어 이해할 수 있을까?

> [!question] 핵심질문
> OSI 모델은 실제 네트워크 프로토콜을 정확히 일곱 조각으로 나눈 구현 규칙일까, 통신 기능을 이해하기 위한 참조 모델일까?

## 한 문장으로 이해하기

**OSI 7계층**은 네트워크 통신에 필요한 기능을 역할별로 나누어, 각 계층이 바로 아래 계층의 기능을 이용하고 바로 위 계층에 서비스를 제공하도록 설명하는 **참조 모델**이다.

## 왜 계층으로 나눌까?

네트워크 통신 전체를 하나의 기능으로 구현하면 프로토콜이나 장비 하나를 바꿀 때 다른 부분에도 큰 영향을 줄 수 있다. 역할을 계층별로 분리하면 다음과 같은 장점이 있다.

- 각 계층의 책임과 인터페이스를 독립적으로 이해할 수 있다.
- 특정 계층의 프로토콜이나 장비를 다른 구현으로 교체하기 쉽다.
- 장애가 발생한 위치를 계층별로 좁혀 진단할 수 있다.
- 서로 다른 제조사와 시스템이 공통 기준에 맞춰 통신할 수 있다.

## 계층별 역할

| 계층 | 이름 | 주요 역할 | 대표 프로토콜·기술 | 데이터 단위 |
| --- | --- | --- | --- | --- |
| 7 | 응용 계층 (Application) | 사용자와 애플리케이션에 네트워크 서비스 제공 | HTTP, DNS, SMTP, FTP | 데이터 |
| 6 | 표현 계층 (Presentation) | 데이터 형식 변환, 직렬화, 암호화, 압축 | TLS, JPEG, UTF-8 | 데이터 |
| 5 | 세션 계층 (Session) | 통신 세션의 설정·유지·종료와 동기화 | RPC, NetBIOS | 데이터 |
| 4 | 전송 계층 (Transport) | 프로세스 간 전송, 분할·재조립, 신뢰성·흐름 제어 | TCP, UDP | 세그먼트·데이터그램 |
| 3 | 네트워크 계층 (Network) | 논리 주소 지정과 다른 네트워크까지의 경로 선택 | IP, ICMP, 라우터 | 패킷 |
| 2 | 데이터 링크 계층 (Data Link) | 같은 링크 안에서 프레임 전달, MAC 주소 사용, 오류 검출 | Ethernet, Wi-Fi, 스위치 | 프레임 |
| 1 | 물리 계층 (Physical) | 전기·광·무선 신호를 이용한 비트 전송 | 케이블, 광섬유, 허브, 리피터 | 비트 |

> [!NOTE] 프로토콜을 한 계층에만 고정하기 어려울 수 있다
> OSI는 개념을 분리하는 참조 모델이다. 실제 인터넷 프로토콜과 소프트웨어는 여러 계층의 기능을 함께 수행하기도 한다. 예를 들어 TLS는 흔히 표현 계층의 예로 설명하지만, 실제 TCP/IP 구조에서는 응용 계층과 전송 계층 사이에서 사용된다.

## 각 계층에서 일어나는 일

### 7계층: 응용 계층

사용자가 이용하는 애플리케이션에 네트워크 기능을 제공한다. 브라우저가 웹 서버에 HTTP 요청을 만들거나 DNS로 도메인 이름에 해당하는 IP 주소를 조회하는 과정이 여기에 해당한다.

### 6계층: 표현 계층

서로 다른 시스템이 같은 데이터를 해석할 수 있도록 표현 형식을 맞춘다. 문자 인코딩, 직렬화, 압축, 암호화와 복호화가 대표적인 역할이다.

### 5계층: 세션 계층

두 통신 주체 사이의 대화 상태를 설정하고 유지하며 종료한다. 연결이 끊겼을 때 대화를 복구하기 위한 동기화 지점을 관리하는 것도 세션 계층의 개념에 포함된다.

### 4계층: 전송 계층

IP 주소가 호스트를 찾는다면 포트 번호는 그 호스트 안의 프로세스를 구분한다. TCP와 UDP는 포트 번호를 이용해 데이터를 올바른 애플리케이션으로 전달한다.

TCP는 데이터를 보내기 전에 [[TCP 3-way handshake|3-way handshake로 연결을 설정]]한다. 연결된 뒤에는 [[TCP 흐름 제어와 혼잡 제어|흐름 제어와 혼잡 제어]]를 통해 수신자와 네트워크가 감당할 수 있는 범위에서 데이터를 전송한다.

### 3계층: 네트워크 계층

IP 주소를 바탕으로 출발지에서 목적지까지 패킷이 이동할 경로를 선택한다. 라우터는 패킷의 목적지 IP 주소와 라우팅 테이블을 확인해 다음 경로로 전달한다.

### 2계층: 데이터 링크 계층

같은 네트워크 링크 안에서 노드 간에 프레임을 전달한다. Ethernet 프레임의 MAC 주소, 오류 검출을 위한 FCS 등이 이 계층과 관련된다.

### 1계층: 물리 계층

0과 1을 전기 신호, 빛, 전파와 같은 물리 신호로 바꾸어 매체를 통해 전송한다. 신호의 세기, 전송 속도, 케이블 규격과 커넥터 형태 등이 이 계층의 관심사다.

## 캡슐화와 역캡슐화

송신 측에서는 상위 계층의 데이터에 각 계층의 제어 정보를 붙이는 **캡슐화**가 일어난다. 수신 측에서는 헤더를 차례로 해석하고 제거하는 **역캡슐화**가 일어난다.

```text
송신 측
응용 데이터
   ↓ TCP 헤더 추가
TCP 세그먼트
   ↓ IP 헤더 추가
IP 패킷
   ↓ Ethernet 헤더·트레일러 추가
Ethernet 프레임
   ↓ 신호로 변환
비트 전송

수신 측
비트 → 프레임 → 패킷 → 세그먼트 → 응용 데이터
```

예를 들어 브라우저가 만든 HTTP 요청은 TCP 세그먼트에 담기고, 다시 IP 패킷과 Ethernet 프레임에 담겨 전송된다. 각 계층은 자신에게 필요한 헤더만 해석하고 나머지 데이터는 상위 계층에 전달한다.

## TCP/IP 모델과의 관계

실제 인터넷에서는 OSI 모델보다 TCP/IP 모델을 더 직접적으로 사용한다. 두 모델의 계층 수는 다르지만 역할은 다음과 같이 대응해 이해할 수 있다.

| OSI 모델 | TCP/IP 모델 | 예시 |
| --- | --- | --- |
| 응용·표현·세션 계층 | 응용 계층 | HTTP, DNS, TLS |
| 전송 계층 | 전송 계층 | TCP, UDP |
| 네트워크 계층 | 인터넷 계층 | IP, ICMP |
| 데이터 링크·물리 계층 | 네트워크 접근 계층 | Ethernet, Wi-Fi |

## TCP 통신을 계층으로 따라가기

TCP 기반 애플리케이션의 통신 흐름을 OSI 모델과 연결하면 다음과 같다.

```text
응용 계층: 애플리케이션이 전송할 데이터를 만든다
    ↓
전송 계층: [[TCP 3-way handshake]]로 연결을 설정한다
    ↓
전송 계층: [[TCP 흐름 제어와 혼잡 제어]]로 전송량을 조절한다
    ↓
네트워크 계층: IP 패킷의 경로를 선택한다
    ↓
데이터 링크·물리 계층: 프레임을 신호로 전송한다
```

## 내가 이해한 방식

OSI 7계층은 택배 배송을 역할별로 나눈 것과 비슷하다.

- 응용 계층은 보낼 물건과 요청을 준비한다.
- 표현 계층은 포장 형식과 내용 표현을 맞춘다.
- 세션 계층은 배송에 관한 대화의 시작과 끝을 관리한다.
- 전송 계층은 물건을 나누고 순서와 도착 여부를 관리한다.
- 네트워크 계층은 목적지까지 이동할 경로를 정한다.
- 데이터 링크 계층은 한 구간에서 다음 지점으로 전달한다.
- 물리 계층은 도로·철도·항공과 같은 실제 운송 수단을 제공한다.

비유는 역할을 기억하는 데 유용하지만, 실제 프로토콜이 OSI 계층과 정확히 일대일로 대응하는 것은 아니다.

## 자주 하는 오해

### OSI 7계층은 실제 인터넷 구현 그 자체다

OSI는 통신 기능을 나누어 설명하기 위한 참조 모델이다. 실제 인터넷은 주로 TCP/IP 모델과 프로토콜 집합을 사용한다.

### 장비는 반드시 하나의 계층에서만 동작한다

장비의 주요 기능을 특정 계층으로 설명할 수는 있지만, 실제 장비는 여러 계층의 정보를 함께 처리할 수 있다. 예를 들어 L3 스위치는 데이터 링크 계층과 네트워크 계층의 기능을 수행한다.

### 송신할 때 데이터가 일곱 번 복사된다

캡슐화의 핵심은 각 계층이 필요한 제어 정보를 논리적으로 추가하는 것이다. 실제 구현에서 데이터가 항상 계층마다 전체 복사되는 것은 아니다.
