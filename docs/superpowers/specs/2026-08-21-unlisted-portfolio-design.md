# 링크 전용 취업 포트폴리오 설계

## 목적

기존 `projects` 컬렉션은 공개 기술 문서로 유지하고, 채용 담당자가 전달받은 링크로만 접근하는 취업용 포트폴리오 문서를 별도 `portfolio` 컬렉션으로 제공한다. 포트폴리오는 프로젝트의 사용법을 반복하지 않고 지원자의 역할, 기술적 판단, 검증 결과와 회고를 보여 주는 케이스 스터디다.

이 기능에서 “비공개”는 인증이나 암호화를 뜻하지 않는다. 포트폴리오 URL은 직접 요청하면 누구나 열 수 있는 미노출(unlisted) 페이지다. 검색엔진 지침과 사이트 내부 데이터에서 제외하지만 URL 전달, 공개 저장소의 소스 열람 또는 외부 공유를 막지는 않는다. 따라서 포트폴리오에는 공개되어도 되는 취업 자료만 저장한다.

## 범위

### 포함

- `content/portfolio/` 전용 Astro 콘텐츠 컬렉션
- 명시적인 공유 식별자를 사용하는 `/portfolio/<shareId>/` 정적 상세 경로
- 포트폴리오 전용 레이아웃과 Markdown 템플릿
- 첫 포트폴리오 문서인 Signal Hub 케이스 스터디
- 검색엔진, 사이트맵, Pagefind, RSS, 홈, 공개 목록, 지식 그래프, 위키링크·백링크·관련 문서 데이터에서 포트폴리오 제외
- 포트폴리오에서 공개 프로젝트 문서, GitHub, npm 등 공개 증거로 나가는 링크
- 직접 링크 접근과 미노출 계약을 검증하는 자동화 테스트

### 제외

- 로그인, 비밀번호, 만료 링크, 접근 로그 또는 링크 폐기 기능
- 공개 `/portfolio/` 목록 페이지
- 공개 프로젝트 문서에서 포트폴리오로 돌아오는 링크
- 지원 기업별 복수 버전과 PDF 내보내기
- 기존 `knowledge`, `explorations`, `projects`, `logs` 문서 형식 변경

## 정보 구조

공개 기술 문서와 링크 전용 포트폴리오는 서로 다른 책임을 가진다.

```text
/projects/signal-hub/
  공개 기술 문서
  기능, 설치, CLI 사용법, 구조, 제약, 상세 문서

/portfolio/<shareId>/
  링크 전용 채용 케이스 스터디
  30초 요약, 역할, 의사결정, 검증, 결과, 회고
  └─ 공개 프로젝트·GitHub·npm 링크
```

공개 페이지는 포트폴리오 URL을 출력하지 않는다. 포트폴리오만 공개 증거 페이지로 단방향 연결한다.

## 콘텐츠 모델

`portfolioSchema`는 공개 컬렉션의 `commonSchema`와 분리한다. 이 분리는 포트폴리오가 공개 콘텐츠 쿼리나 지식 그래프에 우연히 포함되는 것을 타입과 구조 수준에서 방지한다.

필드는 다음과 같다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `title` | 비어 있지 않은 문자열 | 케이스 스터디 제목 |
| `description` | 비어 있지 않은 문자열 | 메타 설명과 첫 화면 요약 |
| `shareId` | 안전한 단일 URL 세그먼트 | 직접 공유 경로. 파일명으로 대체하지 않음 |
| `project` | 안전한 POSIX 상대 경로 | 공개 `/projects/<project>/` 문서 경로 |
| `targetRole` | 비어 있지 않은 문자열 | 지원 직무 |
| `period` | 비어 있지 않은 문자열 | 프로젝트 기간 표시 |
| `projectType` | 비어 있지 않은 문자열 | 개인·팀 등 프로젝트 형태 |
| `role` | 비어 있지 않은 문자열 배열 | 실제 담당 범위 |
| `tags` | 비어 있지 않은 문자열 배열 | 기술 스택 |
| `updated` | 날짜 | 포트폴리오 갱신일 |
| `draft` | 불리언, 기본값 `true` | 프로덕션 정적 경로 생성 여부 |
| `repository` | 선택적 HTTPS URL | GitHub 등 저장소 |
| `package` | 선택적 HTTPS URL | npm 등 배포 패키지 |
| `demo` | 선택적 HTTPS URL | 실행 가능한 데모 |

`shareId`는 `/`, `\\`, `.`, `..`, 쿼리, 프래그먼트와 퍼센트 인코딩을 허용하지 않는 단일 세그먼트다. 예측 불가능성을 보조하기 위해 문서 이름과 별개의 충분히 긴 식별자를 사용하지만, 이는 접근 제어로 간주하지 않는다.

## 렌더링

`src/pages/portfolio/[shareId].astro`가 `portfolio` 컬렉션을 읽는다. 개발 환경에서는 초안을 포함하고, 프로덕션에서는 `draft: false`만 정적 경로로 생성한다. 경로는 반드시 `shareId`에서 생성하며 파일명이나 제목을 폴백으로 사용하지 않는다.

`PortfolioLayout.astro`는 기존 `BaseLayout.astro`의 사이트 헤더, 푸터, 반응형 토큰을 재사용하되 공개 문서용 백링크, 관련 지식, 분야 신호와 작성일 메타데이터를 렌더링하지 않는다. 첫 화면에는 다음 정보를 배치한다.

- 프로젝트명과 한 줄 설명
- 목표 직무, 기간, 프로젝트 형태
- 담당 역할과 기술 스택
- 공개 프로젝트 문서, 저장소, 패키지, 데모 중 존재하는 링크

본문은 Markdown으로 작성하고 다음 순서를 표준으로 삼는다.

1. 30초 요약
2. 문제와 제약
3. 내가 담당한 범위
4. 핵심 기술적 의사결정
5. 검증과 결과
6. 한계와 다음 개선

## 미노출 계약

포트폴리오 페이지는 다음 조건을 모두 만족해야 한다.

1. `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet">`를 출력한다.
2. Pagefind가 페이지의 본문, 헤더와 푸터를 인덱싱하지 않도록 최상위 `body`를 제외 표시한다.
3. Astro sitemap 통합의 `filter`에서 `/portfolio/` 경로를 제외한다.
4. `getPublicEntries()`가 사용하는 공개 콘텐츠 종류에 `portfolio`를 추가하지 않는다.
5. 커스텀 콘텐츠 인덱스의 `CONTENT_KINDS`에 `portfolio`를 추가하지 않는다. 이에 따라 홈 통계, RSS, 지식 그래프, 위키링크 해석, 백링크와 관련 문서에서도 제외된다.
6. `/portfolio/index.astro`를 만들지 않고 내비게이션에도 항목을 추가하지 않는다.
7. 공개 콘텐츠와 템플릿에는 포트폴리오 링크를 추가하지 않는다.

`robots.txt`에서 경로를 `Disallow`하지 않는다. `Disallow`는 크롤러가 페이지의 `noindex` 메타를 읽지 못하게 할 수 있고, 보안 기능도 아니기 때문이다. 미노출은 sitemap 제외와 페이지별 robots 메타로 처리한다.

## Signal Hub 케이스 스터디

첫 문서는 기존 `content/projects/signal-hub.md`의 사용 설명을 복제하지 않는다. 공개된 사실만 사용해 다음을 중심으로 작성한다.

- 서버·스케줄러·대시보드 없이 시계열 규칙을 재현 가능하게 검증하려는 문제
- 결정론적 신호 ID와 점수, SQLite 중복 방지, 단방향 패키지 경계
- CSV 입력부터 탐지·점수화·저장·JSON 출력까지의 담당 범위
- 빌드, 테스트, 타입 검사, 감사, 패키지 구성 검사, 격리 설치와 CLI 실행을 묶은 릴리스 검증
- 공개 npm 패키지 `csv-to-signal` 0.3.0이라는 결과
- 단순 CSV 파서, 로컬 실행, 비연결 커넥터라는 현재 한계

검증되지 않은 성능 수치, 사용자 수, 기여율 또는 비즈니스 성과는 작성하지 않는다.

## 테스트 전략

TDD 순서는 다음과 같다.

1. 스키마 테스트에서 올바른 포트폴리오 frontmatter와 템플릿을 허용하고 위험한 `shareId`, HTTP 외부 링크와 누락된 역할을 거부하는 실패를 먼저 확인한다.
2. 정적 통합 테스트에서 직접 공유 경로가 생성되고 공개 `/portfolio/` 목록이 생성되지 않으며 robots 메타와 Pagefind 제외 속성이 존재하는 실패를 먼저 확인한다.
3. 같은 빌드 결과의 sitemap, RSS, 홈, 검색 인덱스와 콘텐츠 인덱스에 포트폴리오 제목·경로가 없다는 실패를 먼저 확인한다.
4. 기존 콘텐츠 스키마, 경로, 검색, 그래프와 접근성 테스트를 모두 다시 실행한다.

## 완료 조건

- Signal Hub 포트폴리오 직접 URL이 프로덕션 빌드에서 열리고 유효한 HTML을 제공한다.
- `/portfolio/` 목록 경로가 생성되지 않는다.
- 페이지가 지정된 robots 메타와 Pagefind 전체 제외 속성을 가진다.
- sitemap, RSS, Pagefind 검색 결과, 홈 HTML, 콘텐츠 인덱스와 지식 그래프에 포트폴리오 URL·제목이 없다.
- 공개 프로젝트 문서와 내비게이션에 포트폴리오 링크가 없다.
- 포트폴리오에서 공개 프로젝트, GitHub와 npm 링크를 제공한다.
- `npm run verify`와 관련 Playwright 테스트가 통과한다.
