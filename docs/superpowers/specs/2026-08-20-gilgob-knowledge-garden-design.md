# gilgob Knowledge Garden 설계

- 작성일: 2026-08-20
- 사이트 이름: gilgob
- 작성자 및 GitHub 사용자명: internalforces
- 기본 언어: 한국어
- 배포 방식: Astro 정적 빌드와 GitHub Pages

## 1. 목적

gilgob은 시간순 게시물이 중심인 개발 블로그가 아니라, internalforces가 평생 확장하는 개인 지식 베이스이자 Digital Garden이다. Computer Science, Data & Mathematics, AI, Finance, Research, Projects, Learning을 한곳에서 관리하고 날짜보다 분야, 태그, 위키링크, 숙련 상태를 통해 탐색한다.

사이트는 다음 역할을 함께 수행한다.

- 재사용할 수 있는 개념 설명서
- 아직 결론이 나지 않은 탐구 기록
- 결과보다 의사결정과 배움을 남기는 프로젝트 기록
- 짧고 지속적인 학습 로그
- 현재 알고 있는 것을 보여주는 스킬 트리
- 지식 사이의 관계를 보여주는 그래프
- GitHub 활동과 학습 성장을 함께 보여주는 개인 포트폴리오

## 2. 범위

첫 공개 버전에 다음 기능을 포함한다.

- 전체 한국어 사용자 인터페이스
- Knowledge, Exploration, Project, Learning Log의 네 콘텐츠 유형
- 분야, 태그, 상태, 날짜 기반 목록과 필터
- 한국어 전체 검색 및 `Ctrl/Command + K` 검색 창
- Obsidian 위키링크, 첨부 이미지, 콜아웃, 백링크
- 관련 글과 다음 탐구 질문
- 계층형 스킬 트리와 연결 글
- 필터 가능한 대화형 지식 그래프
- GitHub 최근 1년 기여 캘린더와 최근 공개 활동
- 반응형 레이아웃, 키보드 탐색, 접근성 대체 표현
- RSS, 사이트맵, Open Graph, GitHub Pages 자동 배포

첫 버전에서는 댓글, 계정, CMS, 서버 검색, 다크 테마, 다국어 UI를 구현하지 않는다.

## 3. 기술 접근법

정적 우선 통합형을 사용한다.

- Astro의 Content Collections와 `glob()` 로더가 저장소 루트의 `content/`를 직접 읽는다.
- Obsidian은 같은 `content/` 폴더를 Vault로 연다.
- Markdown 확장, 관계 계산, GitHub 통계 수집은 빌드 시 수행한다.
- 검색과 지식 그래프의 상호작용만 작은 클라이언트 아일랜드로 제공한다.
- 완성된 정적 파일은 GitHub Pages에 배포한다.

이 구조는 별도 콘텐츠 복사, 데이터베이스, 런타임 서버를 요구하지 않는다.

## 5. 콘텐츠 모델

모든 Markdown과 MDX 문서는 다음 공통 필드를 가진다.

```yaml
title: "B-Tree는 왜 DB Index에 사용될까?"
description: "B-Tree가 디스크 기반 인덱스에 적합한 이유를 정리한다."
category: "Database"
tags: ["B-Tree", "Index", "Oracle"]
created: 2026-08-20
updated: 2026-08-20
draft: false
aliases: ["B-Tree Index"]
featured: false
```

폴더가 콘텐츠 유형과 기본 URL을 결정한다.

| 폴더 | 유형 | URL | 추가 상태 |
|---|---|---|---|
| `knowledge/` | 정리된 지식 | `/knowledge/...` | `seed`, `growing`, `mastered` |
| `explorations/` | 탐구 노트 | `/explorations/...` | `active`, `paused`, `complete` |
| `projects/` | 프로젝트 | `/projects/...` | `idea`, `building`, `maintained`, `archived` |
| `logs/` | 학습 로그 | `/logs/...` | 상태 없음 |

파일 경로를 기본 slug로 사용한다. 선택적 `slug` 필드가 있으면 해당 값을 URL에 사용한다. 날짜는 ISO 형식으로 정규화하고, `updated`가 없으면 `created`를 사용한다. `draft: true` 문서는 개발 환경에서만 렌더링한다.

카테고리는 초기 상위 분야를 제공하지만 문자열로 유지하여 새 분야를 코드 변경 없이 추가할 수 있게 한다. 초기 분야는 Computer Science, Data & Mathematics, AI, Finance, Research, Projects, Learning이다. UI에서는 한국어 표시 이름을 사용한다.

## 6. Obsidian 호환 규칙

지원 문법은 다음과 같다.

- `[[문서]]`
- `[[문서|표시 이름]]`
- `[[문서#제목]]`
- `![[attachments/image.png]]`
- Obsidian 콜아웃
- 일반 Markdown 링크, 표, 각주, 코드 블록

위키링크는 Unicode NFC 정규화 후 다음 순서로 해석한다.

1. 확장자를 제외한 상대 파일 경로의 정확한 일치
2. 문서 제목의 정확한 일치
3. `aliases`의 정확한 일치
4. 대소문자를 무시한 제목 또는 별칭 일치

둘 이상의 문서가 같은 제목이나 별칭을 가지면 빌드를 중단한다. 존재하지 않는 위키링크는 빌드를 계속하되 경고를 출력하고, 본문에서는 `아직 작성되지 않음` 상태로 표시한다. 코드 블록과 인라인 코드 안의 대괄호는 링크로 처리하지 않는다.

## 7. 파생 데이터 파이프라인

빌드는 다음 순서로 진행한다.

1. 모든 콘텐츠 파일을 로드하고 스키마를 검사한다.
2. slug, 제목, 별칭, 파일 경로를 포함한 문서 인덱스를 만든다.
3. Markdown AST에서 위키링크와 첨부를 변환한다.
4. 문서 간 명시적 링크를 수집하고 역방향 백링크를 계산한다.
5. 카테고리와 태그를 포함한 그래프 노드와 간선을 만든다.
6. 페이지별 관련 글과 전체 통계를 계산한다.
7. Astro가 정적 HTML을 생성한다.
8. Pagefind가 완성된 HTML에서 한국어 검색 인덱스를 만든다.

콘텐츠 정규화, 링크 해석, 그래프 생성은 UI와 분리된 순수 함수로 구현한다. 검색, 백링크, 그래프, 홈 통계가 동일한 정규화 결과를 사용하여 화면 사이의 수치 불일치를 방지한다.

## 8. 정보 구조와 화면

### 8.1 전역 내비게이션

상단 내비게이션은 홈, 지식, 탐구, 프로젝트, 학습 기록, 스킬 트리, 지식 그래프로 구성한다. 오른쪽에는 통합 검색 버튼과 GitHub 프로필 링크를 둔다. 모든 화면에 본문 바로가기와 현재 위치 표시를 제공한다.

### 8.2 홈

홈은 다음 순서로 구성한다.

1. gilgob 소개와 넓은 두 줄 이내의 제목
2. `Ctrl/Command + K` 통합 검색
3. 주요 분야 탐색
4. 현재 탐구 중, 스킬 신호, 지식 성장 패널
5. 최근 학습 기록
6. 주요 프로젝트
7. GitHub 기여 캘린더와 최근 활동
8. 전체 지식과 프로젝트로 이동하는 하단 행동 영역

### 8.3 목록

목록은 콘텐츠 유형, 분야, 태그, 상태, 날짜로 필터링한다. 활성 필터를 URL query string에 반영해 링크를 공유하거나 새로고침해도 상태가 유지된다. JavaScript가 없으면 유형별 전체 목록을 서버가 생성한 정적 HTML로 제공한다.

### 8.4 글 본문

데스크톱은 왼쪽 관련 분야, 중앙 본문, 오른쪽 목차의 세 영역을 사용한다. 본문 하단에는 백링크, 관련 지식, 다음 탐구 질문을 표시한다. 모바일에서는 본문을 먼저 보여주고 목차와 관련 링크를 접을 수 있는 영역으로 이동한다.

### 8.5 스킬 트리

`content/data/skills.yaml`이 분야, 기술, 상태, 관련 문서 slug를 정의한다. 상태는 `mastered`, `learning`, `planned` 세 가지이며 UI에서는 `습득`, `학습 중`, `예정`으로 표시한다. 진척률은 연결 글 개수가 아니라 YAML에 명시된 상태를 기준으로 계산한다. 존재하지 않는 관련 문서 slug는 빌드 오류다.

### 8.6 지식 그래프

문서는 큰 노드, 분야와 태그는 작은 노드로 표현한다. 위키링크는 실선, 공유 태그 관계는 낮은 불투명도의 선으로 구분한다. 사용자는 분야, 글 유형, 태그로 필터링하고 노드를 선택해 요약과 연결 글을 볼 수 있다.

그래프는 해당 페이지에서만 Preact와 Cytoscape를 로드한다. 모바일은 선택 노드 중심의 축소 그래프를 기본으로 사용한다. 그래프와 동일한 내용을 계층형 링크 목록으로 제공하여 키보드와 스크린 리더에서도 탐색할 수 있게 한다.

## 9. 검색

Pagefind가 정적 HTML에서 제목, 설명, 본문, 태그, 분야를 색인한다. 초안, 내비게이션, 반복 푸터는 색인에서 제외한다. 검색 결과는 제목, 유형, 분야, 일치 문맥을 보여준다.

검색 UI는 처음 열 때만 인덱스 클라이언트를 로드한다. 한국어 입력 조합 중에는 검색을 실행하지 않고 조합 완료 후 짧은 debounce를 적용한다. 화살표, Enter, Escape로 모든 검색 작업을 수행할 수 있다.

## 10. GitHub 활동 통계

대상 계정은 `internalforces`다.

- GraphQL `ContributionsCollection`에서 최근 1년 기여 캘린더와 합계를 가져온다.
- REST Events API에서 최근 공개 활동을 가져온다.
- 토큰은 GitHub Actions 빌드 환경에서만 사용하며 클라이언트 번들에 포함하지 않는다.
- 수집 결과는 빌드 캐시에 저장한다.
- API 요청이 실패하면 가장 최근 캐시를 사용한다.
- 캐시가 없는 첫 빌드에서 요청까지 실패하면 빈 상태를 렌더링하고 전체 빌드는 계속한다.
- `push`와 하루 한 번의 `schedule` 이벤트가 사이트를 다시 빌드한다.

최근 공개 이벤트는 GitHub API 제한에 따라 최근 30일 범위의 보조 지표로만 사용한다. 전체 활동량으로 오해할 수 있는 합계는 표시하지 않는다.

## 11. 시각 시스템

기본 방향은 Quiet System 75%, Midnight Lab UI 25%다.

- 캔버스: 옅은 청회색
- 표면: 흰색
- 본문: 짙은 남색
- 탐색과 링크: 선명한 파란색
- 진행 상태와 활성 신호: 민트색
- 레이아웃: 최대 폭 1280px의 12열 그리드
- 구성: 구분선 중심, 약한 그림자, 절제된 둥근 모서리
- 타이포그래피: 한국어 산세리프와 숫자·코드용 모노스페이스

홈과 목록은 넓은 제목, 많은 여백, 빠른 탐색을 우선한다. 통계와 그래프 영역만 레이더, 진행 막대, 신호 점 등 Midnight Lab의 계기판 언어를 사용한다. 전체 배경을 어둡게 만들거나 장식용 배지를 반복하지 않는다.

## 12. 모션과 접근성

모션은 정보 변화에만 사용한다.

- 홈 제목과 검색창의 짧은 진입
- 통계 진행 막대의 최초 1회 변화
- 그래프 필터와 노드 선택 전환
- 클릭 가능한 카드의 1~2px 이동과 테두리 변화

`prefers-reduced-motion`에서는 비필수 모션을 제거한다. 포커스 표시, 본문 바로가기, 충분한 색 대비, 키보드 검색, 그래프의 텍스트 대체 표현을 제공한다. 상태는 색상만으로 구분하지 않는다.

## 13. SEO와 배포

각 공개 문서는 canonical URL, 제목, 설명, Open Graph 메타데이터를 가진다. RSS는 최신 공개 글을 유형과 관계없이 제공하고, 사이트맵에는 공개 문서만 포함한다.

기본 GitHub Pages 주소는 원격 저장소 이름을 기준으로 `https://internalforces.github.io/gilgob/`로 설정한다. 저장소 이름이나 사용자 도메인이 달라지면 GitHub Actions의 `SITE_URL`과 `BASE_PATH` 환경 값을 함께 변경한다. 모든 내부 링크와 정적 자산 경로는 Astro의 base path를 따른다.

## 14. 오류 처리

다음 문제는 빌드를 중단한다.

- 필수 frontmatter 누락 또는 잘못된 상태 값
- 중복 slug
- 중복 제목 또는 별칭으로 인한 위키링크 모호성
- 스킬 트리에서 존재하지 않는 문서를 참조

다음 문제는 경고 후 빌드를 계속한다.

- 아직 존재하지 않는 위키링크
- 누락된 선택적 첨부 파일
- GitHub API 또는 검색 인덱스의 외부 처리 실패

검색, 그래프, GitHub 데이터가 비어 있어도 페이지 구조와 다른 탐색 기능은 유지한다.

## 15. 테스트 전략

- 단위 테스트: 스키마 정규화, 위키링크 파싱, 별칭 해석, 백링크, 그래프 간선, 스킬 진척률
- 통합 테스트: Markdown 렌더링, 초안 제외, 정적 경로, Pagefind 메타데이터, GitHub 캐시 fallback
- E2E 테스트: 홈 탐색, `Ctrl/Command + K` 검색, 목록 필터 URL 동기화, 글 백링크, 스킬 링크, 그래프 필터, 모바일 내비게이션
- 품질 검사: Astro type check, 정적 빌드, 링크 검사, 접근성 자동 검사

테스트 fixture에는 한국어 제목, Unicode 조합, 별칭, 깨진 링크, 중복 링크, 이미지 임베드가 포함된다.

## 16. 완료 기준

첫 버전은 다음 조건을 모두 만족할 때 완료된다.

- `content/`를 Obsidian Vault로 열어 작성한 문서가 복사 없이 사이트에 반영된다.
- 네 콘텐츠 유형의 예제 문서가 목록과 본문에 올바르게 표시된다.
- 위키링크, 백링크, 첨부, 콜아웃이 변환된다.
- 한국어 검색과 필터가 키보드 및 모바일에서 동작한다.
- 스킬 트리 항목이 관련 Knowledge 글로 연결된다.
- 지식 그래프가 콘텐츠 관계를 표시하며 텍스트 대체 탐색을 제공한다.
- GitHub 기여 캘린더가 표시되고 API 실패 시 fallback이 동작한다.
- GitHub Pages의 base path 아래에서 내부 링크와 자산이 깨지지 않는다.
- 자동 테스트와 정적 빌드가 통과한다.
